# 毫芒 Hairline｜参赛材料提纲

更新：2026-10-13。具体提交格式、评分和截止时间以本届官方通知为准，提交前复核。

## 材料主线

1. **问题与场景**：晶圆显微图缺陷不仅要“找得到”，还要回答严重度和处置；目标用户为质检员及复核工程师。
2. **方案**：定位与序数分级模型提供证据，AgentArts 按置信度分流并处理边界样本；展示角色输入、工具调用和输出，避免只展示聊天界面。
3. **验证**：官方 baseline 复现、相同条件下的单变量消融、三指标和错误案例。当前结果写“待实测”。
4. **应用价值**：减少重复筛查，让可疑和边界样本进入人工复核；不声称已在产线部署或替代现有设备。
5. **团队**：A 主导模型，B 主导平台和产品，C 主导数据、服务与评测；B/C 同时参与算法。

## 5. 系统技术方案（设计稿）

以下是拟在 AgentArts 落地的设计，**不是已实现能力**。平台仍在公测申请阶段；模型、阈值、知识库和人工复核界面均需验证。独立流程图见 [Agent 工作流程图](05-Agent工作流程图.md)。

### 5.1 Agent 总体架构

系统分为四层：**工作台**接收图片并呈现证据；**AgentArts 编排层**负责检测、分拣、仲裁和异常路由；**视觉推理服务**输出框、掩码、缺陷类别、四档严重度和置信度；**知识库与规则层**提供经审核的分级定义、复核要点和处置规则。实验评测独立于 AgentArts，不用 Agent 的自然语言回答计算模型指标。

| 角色 | 独立目标 | 可用能力 | 结构化输出 |
|---|---|---|---|
| 检测 Agent | 取得可信的图像检测结果 | 调用视觉推理工具；校验字段、模型版本和演示标记 | `detection_result` 或 `tool_error` |
| 分拣 Agent | 为每张图选择处置路径 | 读取检测结果和已发布的阈值规则 | `route`、`reason_code`、`policy_version` |
| 仲裁 Agent | 说明边界和不确定性，形成复核任务 | 检索知识库；对照视觉证据和规则 | `review_reason`、`evidence_refs`、`review_questions` |

三者通过同一个 `run_id`、`sample_id` 传递结果；编排层保存工具入参摘要、输出、路由理由、模型/规则/知识库版本。模型和 Agent 都不能直接执行产线放行或返工指令。

### 5.2 Agent 工作流程

1. **输入校验**：工作台创建任务并传递图片引用与样本 ID。检查格式、可访问性和使用许可；受限的 ICME 原图不送往未经许可的公网服务。
2. **检测**：检测 Agent 调用推理服务，检查请求是否成功、结果是否完整、`image_analyzed=true`、`demo_only=false`，以及框坐标和置信度范围是否有效。当前 mock 仅用于链路演示，不能通过真实结果校验。现有 v0 接口尚无掩码和模型版本字段，接真模型时需补齐。
3. **分拣**：分拣 Agent 依据严重度、置信度和规则版本选择“常规处置建议”或“仲裁/人工复核”。边界档、低置信度、结果冲突进入复核；阈值由验证数据校准，当前不填固定数值。
4. **仲裁**：仲裁 Agent 检索适用规则，列出缺陷位置、相邻档争议、缺少的证据及建议人工核查的问题。知识库没有适用规则、检索结果矛盾或证据不足时，明确弃权并提交人工复核。
5. **展示与记录**：工作台显示原图、标注、模型结果、分流理由、知识条目引用和人工处理状态。批次结果逐图汇总；任一单图失败不伪装成“无缺陷”。

工具超时或返回格式错误时，编排层可按相同 `run_id` 进行有限重试；仍失败则生成失败记录并转人工。重试次数、超时和幂等方式在平台实装时确定。

### 5.3 多 Agent 协同机制

**交接契约**：检测结果是分拣的唯一图像事实来源；分拣只决定路径，不改写缺陷框或分级；仲裁读取检测结果、路由理由和知识库证据，不凭语言推测新缺陷。三个角色的输出都使用结构化字段，最终文案由这些字段生成。

**冲突处理**：如果整体档位与缺陷级档位不一致、置信度缺失、证据引用失效，或仲裁意见与分拣建议冲突，状态置为 `needs_review`；保留原始结果和各角色意见，不在后台静默覆盖。人工复核前不产生确定的放行结论。

**协同证据**：每次执行保存 AgentArts 调用详情、工具调用结果和路由决定。验收时至少展示一条常规路径、一条边界档路径和一条工具失败路径，证明角色交接真实发生；具体能力以平台开通后的实际功能验证。

### 5.4 知识库增强推理机制

知识库计划收录：四档严重度定义、七类缺陷的描述、复核操作要点、处置规则及来源文档。每条知识保留 `source_id`、版本、适用范围、审核人和生效日期；未经确认的经验性描述单独标注，不与已批准规则混用。

仲裁时以“缺陷类别 + 候选档位 + 争议点”检索，返回少量相关条目及原文出处。Agent 只用检索结果解释**为什么需要复核、复核什么**；知识库不能代替视觉测量，也不能把低置信度预测变成高置信度事实。检索不到适用条目时返回 `no_applicable_rule`，由人工处理。知识库内容、切分方式和检索效果均待实际构建与检查。

### 5.5 决策与人机协同机制

| 条件 | 系统输出 | 人的动作 |
|---|---|---|
| 结果有效、置信度达到已校准阈值、非边界档 | 放行或返工**建议**及依据 | 按现场制度确认 |
| Marginal NG、低置信度、相邻档冲突 | `needs_review`、争议点、可视证据 | 质检员复核；必要时工程师裁定 |
| 工具失败、模拟结果、知识库缺失或规则冲突 | `blocked` / `needs_review`，注明原因 | 人工接管，不自动放行 |

人工复核界面需记录复核人、时间、结论和理由，并保留模型原判；人工更改不反写原始预测。经授权且许可允许的复核样本可进入后续误差分析和再训练候选集，训练前仍需单独审核。系统只辅助决策，不宣称具备生产级自动放行能力。
