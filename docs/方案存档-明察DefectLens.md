> 定位：半导体晶圆表面缺陷的**定位 + 细粒度严重度分级**。工业质检的"出厂前先查一下"。

> 版本：v1（2026-10-10 23:xx）。**本文件所有数字均标注来源；未实测的一律写"待实测"，估算一律标"估算"。**

这不是退而求其次——"在公开基准上超过当届冠军"这句话，在答辩台上比"我参加了个比赛"更硬（往届特等奖《Remarkably》走的就是这一类形状）。但**承诺等级必须写对**：我们承诺的是"可验证的分数"，不是"奖杯"。

**赛场 = 华为 ICT 大赛创新赛 · 赛题二**（基于 AgentArts 平台的 Agent 设计与应用）。这是要交作品、要拿奖的地方，评委是华为的人。

**为什么需要一把外部尺子**：华为 ICT 大赛**没有可刷的公开算法榜**，评委也无法当场验算模型好坏。往届特等奖的共同形状是"**一件真的硬技术 + 外面套一个平台化系统**"（WSI 病理推理加速 4 倍、手写中文 OCR）。**ICME 的分数就是"那件硬技术"的证明**，它服务于 ICT 大赛的评分表，不替代它。

| 华为 ICT 大赛评分维度（各校通知口径） | 由谁支撑 |
|---|---|
| 作品创新性 | ICME 冻结榜上的可复现超越（同一公式、同一测试集） |
| 系统复杂性·技术复合性 | 多阶段管线（筛选 / 分割 / 序数头 / 集成）+ AgentArts 编排 |
| 功能完备性 | 上传 → 筛选 → 定位 → 分级 → 处置 → 对标，全链路可现场验证 |
| 商业价值·社会效益 | 精密制造质检真需求，分级直接关联"放行还是返工"的成本 |
| 答辩表现 | 可当场打开冻结榜核对分数，每个开关都对得上论文实证 |

**必须防的一个漏洞**：若作品退化成"一个检测模型 + 一个调用界面"，在赛题二下会被问"**这跟 AgentArts 有什么关系**"。因此外壳必须是**真的 Agent 行为**，而不是 API 包装：

- **自主分流**：按置信度决定"直接放行 / 送人工复检"，而不是一律输出结果。
- **可解释**：给出判这一档的视觉证据（哪块区域、什么纹理特征）。
- **主动上报不确定**：遇到 Marginal NG / NG 边界样本时标出"我判不准，建议人工"——同时呼应论文点名的全场瓶颈。
- **跨批次校准**：在多批数据间累积，动态调整阈值（纯模型没有这个行为）。
- **多角色**：分拣 / 检测 / 仲裁，各有工具与职责，不是把一次推理拆成三个名字。

⇒ 这样"多 Agent"是真的（每张图、每个角色都有独立判断与动作），不是硬凑；也让赛题二的合规问题从"勉强及格"变成"主动加分"。

## 一、一句话与机制

**一句话**：在一张晶圆表面显微图里，找出人眼难分的缺陷并框出来，再判断它严重到哪一档。

四档标签（官方原文，序数而非并列）：**Acceptable / Marginal NG / NG / Gross NG**。

**删掉"AI/Agent/多智能体"之后还剩什么**：*定位缺陷 + 判断严重度*。这句话站得住——这是本方案能立项的第一前提。

**机制（外壳合规、内核拿硬话）**：

| 层 | 内容 | 作用 |
|---|---|---|
| 外壳 | AgentArts 上的「质检智能体」：接收图片批次、调用检测内核、汇总工单、给出处置建议（复检 / 返工 / 放行） | 过赛题二；多角色天然（分拣 / 检测 / 仲裁） |
| 内核 | ① 无监督异常筛选 → ② Mask2Former 类实例分割定位 → ③ 序数回归严重度头 | 拿硬话：分数比基线高 |

**内核才是作品的价值所在，外壳是合规与交互层。** 这个分层是有意的，出自对 Track 1 冠军（企业队三 VLM 集成）与 Track 2 冠军（单模型 + 一个头）的对比结论——见第三节。

## 二、为什么是它（五条理由）

1. **有冻结的公开尺子，且不需要任何独家数据。**
   ICME 2026 组委会公开了评价指标、权重、最终排行榜与官方 baseline 代码（`github.com/IDAGrandChallenge/idachallenge-baseline`）。我们在同一把尺子上和 7 支已提交队伍比数。

2. **它是「焊伴」的骨架，而焊伴的死因被补上了。**
   焊伴当年不是不好，是**造不出问题板、拿不到数据**。ICME 这份晶圆缺陷数据集把"数据"这个洞直接填了——这同时满足了你选 B 的初衷（抢新基准首发）。

3. **冠军方案极轻 —— 这是"学生队能做"最硬的证据。**
   Track 2 冠军（山东大学 MVP，0.811）的做法：在 Mask2Former 解码器上**并联一个严重度分类头**，端到端联合训练；**2100 次迭代、batch 8、2×A100、约 30 分钟、无集成、无外部数据**。这不是堆算力预训练，是"复现 + 改一个头"。**你们说能租云 GPU，这条路就通了。**

4. **竞争密度极低。**
   Track 1 只有 14 队提交有效结果，Track 2 **只有 7 队**。前五名挤在 0.795–0.811（差距 0.016），说明**没有队伍拉开差距**，也说明冠军并不是不可追的。

5. **华为不占这条赛道。**
   华为做的是工业智能体平台与制造本体模型（把 AI 接进产线），**不做缺陷检测算法本身**。这是"不同赛道"，不是"同一件事上比层级"——与材料方向（撞 AI4SS）的性质不同。

## 三、公开基准与已发表基线（全部为赛事官方/论文原文数字）

### 3.1 评价公式（出处：挑战赛论文 §II-C）

- **Track 1**：`S = 0.3·S_loc + 0.3·S_cls + 0.4·S_screen`（筛选取最高权重，因为工业界最怕误报）
- **Track 2**：`S = 0.2·S_loc + 0.2·S_cls + 0.6·S_grade`
  - `S_loc` = mIoU
  - `S_cls` = Macro-F1
  - `S_grade` = **QWK（Quadratic Weighted Kappa）**，按序数等级间的平方距离惩罚分歧

> 关键含义：Track 2 有 **60% 的分压在"严重度分级"上**，而分级用的 QWK 正好惩罚"把 NG 判成 Marginal NG"这种**相邻档混淆**。这是本作品的胜负手。

### 3.2 Track 2 最终榜（7 队，来源：挑战赛官网 leaderboard + 论文 Table II）

| 名次 | 队名 | S_loc | S_cls | S_grade | S_Track2 |
|---|---|---|---|---|---|
| 1 | MVP（山东大学） | 0.662 | 0.673 | **0.907** | **0.811** |
| 2 | EVA | 0.689 | 0.667 | 0.885 | 0.802 |
| 3 | Hebut AI | 0.652 | 0.658 | 0.891 | 0.797 |
| 4 | accle | 0.684 | 0.675 | 0.873 | 0.796 |
| 5 | jcjing | 0.684 | 0.674 | 0.872 | 0.795 |
| 6 | limzero | 0.634 | 0.563 | 0.831 | 0.738 |
| 7 | APC_TDC | 0.546 | 0.666 | 0.790 | 0.716 |

**冠军拆解**：0.2×0.662 + 0.2×0.673 + 0.6×0.907 = 0.811（已验算）。
⇒ **最高的那一项已经是 0.907，几乎顶格；真正偏低的是 S_loc 0.662 与 S_cls 0.673。** 这是我们要补的位置（见第四节）。

### 3.3 Track 1 最终榜（前 5，来源同上）

| 名次 | 队名 | S_loc | S_cls | S_screen | S_Track1 |
|---|---|---|---|---|---|
| 1 | FS-Seekers（上海帆声科技） | 0.618 | 0.746 | 0.992 | **0.806** |
| 2 | KZRR_sdu | 0.628 | 0.665 | 1.000 | 0.788 |
| 3 | trios | 0.467 | 0.590 | 1.000 | 0.717 |
| 4 | MVP | 0.628 | 0.587 | 0.842 | 0.701 |
| 5 | APC_TDC | 0.561 | 0.638 | 0.827 | 0.690 |

**为什么我们不押 Track 1**：冠军 FS-Seekers 是**企业队**，方案是 Qwen3-VL-8B(LoRA) + Florence-2(全量微调) + Gemma-4-31B(冻结) 三模型决策级集成 + 扩散模型合成罕见类 + 三级级联后处理。这套东西学生队两个月做不出来。Track 2 冠军那套可以。

### 3.4 数据集规模与获取方式（**这一节是当前唯一未决前提**）

- Track 1：训练 **1492 张**（319 正常 / 1173 异常，带像素级实例标注），测试 **2323 张**（刻意做了光照/纹理/尺度变化以考跨场景泛化）。
- Track 2：测试 **1156 张异常图 / 1388 个缺陷实例**，每个实例带四档严重度标签。训练集与 Track 1 同图，另加严重度标注。
- **获取方式（官方页原文）**："Training dataset will be sent to the contact email address provided in the registration form." ⇒ **要注册（Google Form）+ 邮件发送**，不是点开就下。
- **风险**：赛事已结束，赛事方是否仍发放数据 —— **未验证**。这是提交前必核第一项。
- **Plan B（并行准备，不空等）**：改用公开可下的工业缺陷基准 —— **MVTec-AD、VisA、Real-IAD、MANTA**。它们同类、可下，但**没有 ICME 的四档严重度标签和冻结榜单**。若走 Plan B，"对标冠军"这句话就不成立了，只能改为"在公开基准上超过已发表的异常检测基线"。**两条路的价值差一档，所以要优先争 ICME 数据。**

### 3.5 论文亲口承认的瓶颈与公开方法论（这是我们改进点的出处）

- **瓶颈原句**：数据集作者在总结中写 *"ordinal boundary disambiguation remains a significant hurdle"*——**序数边界消歧仍是重大障碍**，具体就是 **"Marginal NG" 与 "NG" 分不开**。
- **公开的三条方法论**（写在论文与组织方总结里，不是秘密）：
  1. **筛选与检测解耦**：先用无监督异常筛选剔掉正常图，再做重检测器——拿 `S_screen = 1.000` 的队伍都是这么做的。
  2. **序数回归优于多分类**：APC_TDC 队用 **CORN 回归头**替换规则基线后，该队局部分数从 0.441 抬到 0.802。
  3. **VLM 注入领域知识提示**能提升跨场景泛化（Track 1 冠军路线）。

## 四、我们要动的那一处（可单变量消融）

**核心判断：冠军把 0.6 权重的分级做到了 0.907，但 0.2 权重的定位只有 0.662。我们不奢望在 0.907 上再挤出多少，主攻点是"定位 + 分类"这两块短板，并顺手把分级做稳。**

| 我们的改动 | 针对榜单暴露的哪个现象 | 预期可观测效应 |
|---|---|---|
| **定位增强**：更强分割骨干（DINOv2 / InternImage 特征）+ 高分辨率输入 + 多尺度 | S_loc 冠军仅 0.662，是全场短板 | S_loc 目标 ≥ 0.72（待实测） |
| **长尾与类不平衡处理**：逆频率加权 / 稀有类增广 | S_cls 冠军 0.673；榜单第 6 名只有 0.563 | S_cls 目标 ≥ 0.72（待实测） |
| **序数分级做深**：CORN/CORAL 序数头 + 相邻档距离感知损失 + 边界样本重加权 | 论文点名"Marginal NG vs NG 分不开" | S_grade 不低于 0.907，力争抬升（待实测） |
| **决策级集成**：两个分割器预测取并集 + 类别 NMS + 几何规则后处理 | Track 1 冠军正是靠集成拿的第一 | 三指标同向抬升（待实测） |
| （可选）**半监督**：用测试集无标注图的伪标签 | 训练集仅 1492 张，偏小 | 泛化提升（待实测） |

**消融设计**：固定其余全部条件，只逐个打开上面的开关，在冻结测试集上按官方公式出分。目标产出是一张"每打开一个开关、总分涨多少"的表——**这张表就是答辩时最有说服力的东西**，也是评分里"验证与复现"那一栏的分数来源。

**数据（并行推进，不等）**
1. **主线**：你去走注册 + 邮件申请（赛事方联系方式见官网；若回信慢，同步再问一次）。**今天就把邮件发出去**，因为要等回信。

**算力（已确认：实验室可借，不必自费租云）**
- 指导老师可借实验室 GPU ⇒ **不产生租云开销**。但需再确认三点：① **卡型与显存**（能否跑 Mask2Former 级别的分割模型）；② **单次可用时长与排队情况**；③ **是否允许多卡**。
- 退路：若实验室卡不够（显存不足或排队过长），再租云。冠军单次训练约 30 分钟（2×A100）；按**估算**数十机时计，成本随云商与时段波动，**需实际询价后确认**。

**分工与平台上手（按四人现有条件）**

队伍画像：**1 名专职算法（做过图像分割）+ 2 名开发（都能做 Agent，你前后端最强）**。

| 人 | 负责 | 说明 |
|---|---|---|
| 队员 A（专职算法，做过分割） | 内核主线：分割骨干 / 序数头 / 集成 / 消融 | **"那句硬话"所在**；唯一 KPI＝把 S_loc 从 0.662 抬上去（冠军最弱项＝他的老本行） |
| 队员 B（你） | AgentArts 外壳（三角色编排 + 自定义插件）+ 质检工作台界面 + 可视化 | 对外的脸，对上你的前后端强项 |
| 队员 C（开发，能做 Agent，沾过算法） | 内核工程化 + 评测管线：模型包成 HTTP 服务/插件、mIoU/QWK 脚本、消融调度、数据管线 | 站在 A 与 B 中间的桥，兼算法单点的备份 |
| 指导教师 | 算力 + 方向把关 | 已确认可借卡 |

**单点风险**：算法只有 A 一人。缓解＝**C 紧贴 A**（接管数据、评测、接口封装这类重复劳动），A 跑通 baseline 后把调参重复活交出去，自己专注攻关。

**AgentArts 是当前唯一待补项**（现状：看过没做）。补法：先用半天跑通一个最小 Agent（拖一个对话 Agent + 接一个工具 + 跑一次），把平台摸熟再往上加编排。**外壳不依赖 ICME 数据，现在就能开工，不必等邮件。**

## 七、撞车与红线

**三层撞车，逐层说清。**

1. **学术层**：工业缺陷检测是成熟赛道（MVTec-AD 起就是标准任务），ICME 挑战赛本身已有 7–14 队做过。**我们不声称概念首见。** 我们的位置是"在冻结榜上把数做上去 + 完整复现"。
2. **商业层**：工业视觉质检厂商很多（含帆声科技这类已参赛企业）。**同前，"有人做"不是判据**，判据是"能不能说出别人做不到的那一句"——即超额那部分的来路。
3. **华为自家**：华为做工业智能体平台/制造本体模型，**不做缺陷检测算法本身**。分界线清楚，但仍需准备答辩回答："我们做的是算法内核的实测改进，不是产线智能体平台。"

**合规与数据使用**
- ICME 数据使用须遵守其数据条款，参赛材料中注明引用与许可；**不得把数据集本身当我们的产出**。
- 若赛事方要求不得再分发，只本地训练、不随作品分发原始数据。
- 演示只用公开数据或自造样本，不接真实产线的保密图片。

## 九、五维落点与 AgentArts 落点

| 评分维度（各校通知口径，非官方原文） | 落点 |
|---|---|
| 作品创新性 | 不赌品类首见。赌"冻结榜上的可复现超越 + 相邻档混淆这个新指标" |
| 系统复杂性·技术复合性 | **主场**：多阶段管线（筛选/分割/序数头/集成）+ AgentArts 编排 + 评测管线 + 可视化 |
| 功能完备性 | 上传→筛选→定位→分级→处置建议→对标，全链路现场可验证 |
| 商业价值·社会效益 | 半导体/精密制造质检真需求；缺陷分级直接关联"放行还是返工"的成本 |
| 答辩表现 | 每个开关都对得上论文实证，冻结榜可当场核验 |

**AgentArts 落点**：多智能体编排（分拣/检测/仲裁）；自定义 Skill 承载检测与分级；知识库存缺陷类别与处置规则；MCP 接图像处理服务；平台自带观测与效果评估（用来证明管线真在跑）。

## 十、三条放弃声明（诚实）

1. **放弃"再来一次冠军奖杯"。** 赛事已结束，我们做的是**对标分数**——在同一冻结榜、同一公式下超过当届冠军。措辞必须写对，不能暗示我们参赛获奖。
2. **放弃"稳超 0.811"。** 冠军 S_grade 0.907 已近顶格，我们的空间主要在 S_loc / S_cls。**能做到多少取决于实测，方案不预设结论。**
3. **不承诺"生产可用"。** 这是公开基准上的算法改进 + 可交互演示，不是可直接上产线的系统；跨场景泛化是全场未解难题，我们不宣称已解决。
