## 一、总体架构

三层，各层可独立替换：

```
┌─────────────────────────────────────────────┐
│ 展示层  工作台（prototype/，浏览器）              │
│         批次上传 · 定位框+四档色带 · 对标面板      │
├─────────────────────────────────────────────┤
│ 编排层  AgentArts（赛题二指定平台）               │
│         三角色：分拣 / 检测 / 仲裁                │
│         自定义插件 ←→ 公网 HTTPS 推理服务         │
├─────────────────────────────────────────────┤
│ 内核层  推理服务（src/，Python）                  │
│         预处理 → 粗筛 → 分割定位 → 严重度分级      │
├─────────────────────────────────────────────┤
│ 评测层  评测脚本（eval/）                        │
│         mIoU / Macro-F1 / QWK 三指标同算          │
└─────────────────────────────────────────────┘
```

**分层原则**：编排层只依赖接口契约，不关心模型；内核层只依赖数据格式，不关心谁调用；评测层独立，任何人跑同一份数据得出同一组数。

## 二、模块设计（内核层）

| 模块 | 输入 | 输出 | 现状 | 可替换点 |
|---|---|---|---|---|
| 预处理 | 原始图 | 定尺寸张量（默认 1024×1024，与 mock 的 `image_size` 对齐） | 待实现 | 分辨率、归一化参数 |
| 粗筛 | 张量 | 正常/可疑二分类 + 置信度 | 待实现 | 无监督异常检测（Dinomaly 类）或轻量分类器 |
| 分割定位 | 张量 | 每缺陷掩码 + bbox + 类别（7 类） | 待实现 | YOLOv8-seg（官方 baseline）→ 可换更强骨干 |
| 严重度分级 | 掩码特征 | 四档序数标签 + 置信度 | 待实现 | **手工规则 → 学习式序数头（CORN/CORAL）是第一个单变量** |
| 后处理 | 原始输出 | 类别去重、掩码清理、工单汇总 | 待实现 | 几何规则参数 |

**单图处理流**：预处理 → 粗筛（合格批在此短路，不过重模型）→ 分割定位 → 严重度分级 → 后处理 → 返回。粗筛短路是性能设计，也是「分拣」这个 Agent 角色存在的技术依据——不是为凑角色硬拆的。

## 三、接口契约（已与现有代码核对，冻结）

### `POST /v1/inspect`

请求：
```json
{
  "sample_id": "W-0304",
  "image_url": "https://example.invalid/wafer.png"
}
```
- `image_url` **必填**，非空字符串；
- `sample_id` 可省略；两者都给时以 `sample_id` 为键。

响应（真实模型就绪后**保留全部现有字段**，只改三个标记的值）：
```json
{
  "sample_id": "W-0304",
  "mode": "mock",
  "demo_only": true,
  "image_analyzed": false,
  "image_size": {"width": 1024, "height": 1024},
  "grade": "Marginal NG",
  "confidence": 0.63,
  "defects": [
    {
      "category": "scratch",
      "confidence": 0.81,
      "bbox_xyxy": [320, 390, 500, 470],
      "severity": "Marginal NG"
    }
  ],
  "message": "模拟结果：未读取或分析图片，不得作为实测成绩。"
}
```

**字段纪律（写进代码评审）**：
1. `bbox_xyxy` 是基于 `image_size` 的像素坐标，顺序左、上、右、下——不许改成归一化坐标，两边会错位；
2. `grade` 是**序数四档**（Acceptable < Marginal NG < NG < Gross NG），不是并列类别，下游不许当 one-hot 用；
3. `mode` / `demo_only` / `image_analyzed` 三个标记是**防假数据混进评测的唯一闸口**，任何实现不许省略；
4. 真实模型可**增加**字段（如 `mask`、`evidence`），**不许删**或改语义。

### `GET /health`
返回 `{"status":"ok","mode":"mock"}`。真实服务把 `mode` 改成 `model`。

### 错误响应
`400 {"error":"invalid_request","message":"..."}`；未知路径 `404`。请求体上限 65536 字节（当前实现），扩容需同步 `agentarts/README.md`。

## 四、算法管线细节

### 4.1 起点：官方 baseline（复现对象）
- 官方两个 Track 都用 **YOLOv8-seg**；Track 2 分级是**手工规则**：拿掩码面积、框长宽、灰度对比度等指标加权打分再套四档——不是学出来的。
- 复现步骤与验收见 `baseline复现路径-明察DefectLens.md`，这份不重复。

### 4.2 第一个单变量：规则 → 学习式序数头
- 分割输出不变，**只换分级那一段**；CORN / CORAL **先用一个**，不许两个一起上（单变量原则）；
- 护栏：**QWK 任何一次跌破 0.89 即回滚**；每次消融三指标同记。

### 4.3 主攻方向：mIoU
- 当届冠军 QWK 0.907（近顶格）、mIoU 0.662（全场最低）——短板即主攻点，正对队员 A 的分割本行；
- 手段排序：更强分割骨干 → 高分辨率输入 → 多尺度融合 → 掩码质量后处理。**一个一个上**，每个都落消融记录。

### 4.4 训练配置参照
- 冠军量级（参照，非承诺）：2100 次迭代、batch 8、2×A100、约 30 分钟；
- 实际配置按实验室确认的卡型定，落 `runs/`。

## 五、数据流与目录映射

```
data/raw/            ICME 数据 / MVTec-AD 原样解压，只读
   │
   ▼  清洗、划分子集、格式转换（只读不改动 raw）
data/processed/      COCO/ masks 等训练可用格式
   │
   ▼  训练 / 推理
runs/<日期>-<配置>/   config.json + 指标 json + 日志
   │
   ▼
eval/                 三指标脚本；对同一份 processed 数据任何人跑出同一组数
```

**规矩**：`raw` 只读；每次实验一个 `runs/` 子目录；指标 JSON 字段固定（日期/数据集/配置/mIoU/Macro-F1/QWK），便于横向比对。

## 六、部署拓扑

```
本地开发                公网                      AgentArts
mock / 真模型  ──公网化──▶  HTTPS 推理服务  ◀──插件──  三角色智能体
 127.0.0.1:8000    （云服务器 or 内网穿透）              （调试窗口看调用详情）
```

**硬约束**：平台是公有云服务，**只能通过公网访问外部服务，连不到本地/内网**（官方原文）。所以：
1. mock 服务和将来的真模型服务**都必须先部署到公网 HTTPS** 才能挂插件；
2. 决赛要求的「公网可访问、可交互 Demo 页面」是同一个问题的另一面——一次解决两件事；
3. 接入路线**先插件后 MCP**：插件基于 API 创建，直接填 REST 地址 + schema，当天能通；MCP（SSE/streamableHttp）工作量更大，但决赛材料要交「自定义 Skill / MCP 服务说明」，后补；
4. 平台限制记牢：**评估任务基础版 10 次**（消融在本地算）；**应用中 MCP 服务 ≤ 5 个**。

## 七、关键技术决策记录（ADR 简版）

| 决策 | 理由 | 什么情况下推翻 |
|---|---|---|
| 内核起步用 YOLOv8-seg | 官方 baseline 同款，复现有锚点 | 复现成功且确认要冲 mIoU 时换更强骨干 |
| 分级从手工规则换成序数头 | 官方 baseline 与冠军之间唯一被点名的结构差异，单变量干净 | QWK 跌破 0.89 |
| 先插件后 MCP | 插件直接适配 REST，当天能通 | 平台插件 schema 不支持我们的字段时 |
| 外壳先单智能体→工作流→多智能体 | 风险递增，工作流是兜底形态 | 平台多智能体配置确认可行后直接上 |
| 演示数据只用公开集或自造 | 不用产线保密图，合规 | 无 |
| 三层分离（编排/内核/评测） | AgentArts 只认接口，模型可换；评测独立防自说自话 | 无 |
