# 任务分工 · 明察 DefectLens

> 这份文档管**谁在什么时间交付什么**。三条线并行：外壳（AgentArts）/ 内核（算法）/ 材料（初赛），互不等待。
> 版本：v1（2026-10-13）。任务状态随执行更新，**完成一项勾一项，不许自报完成**。

---

## 一、角色与职责

| 角色 | 谁 | 主责 | 唯一 KPI |
|---|---|---|---|
| **队员 A** | 专职算法（做过图像分割） | 检测内核：筛选 / 分割 / 序数头 / 集成 / 消融 | **把 mIoU 从 0.662 那一档抬上去**（当届冠军的短板就是我们的主攻点） |
| **队员 B** | 开发，前后端最强（你） | AgentArts 外壳（三角色编排 + 自定义插件）+ 工作台界面 + 公网部署 | 平台上有一个**真能跑**的应用，且「调用详情」可截图 |
| **队员 C** | 开发，能做 Agent、沾过算法 | A 与 B 之间的桥：HTTP 封装 / 评测脚本 / 数据管线 / 消融调度 | 评测脚本出的数，A 敢直接写进材料 |
| **指导老师** | — | 算力 + 方向把关 | 卡型/显存/时长三问有答案 |

**结构性问题（全项目最大弱点）**：算法只有 A 一人，是单点。缓解只有一条——**C 紧贴 A**：A 跑通 baseline 后，调参、跑评测、跑消融交给 C，A 只做攻关。

**当前三个卡点**：① 数据回信（被动等）；② 卡型未确认（问老师，10 分钟）；③ 公网方案未拍板（0.6）。

## 四、沟通与汇报

1. **周节奏**：每周固定一次 30 分钟同步，三线各报三件事——做完什么 / 卡在哪 / 下周做什么；
2. **口径只在文档里**：`硬约束` 与 `答辩问答口径` 是对外唯一口径来源，**不在群里口头传**，谁传谁改回来；
3. **坏消息不过夜**：卡住超过半天就在同步会上说，不许自己扛到截止日；
4. **完成标准**：任务验收栏全过才算完成，自报完成不算。
