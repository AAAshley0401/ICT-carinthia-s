## 一、合规红线（碰了出局，没有例外）

1. **不暗示参赛获奖**。ICME 2026 已于 4 月收官、7 月颁奖。对外唯一口径：*"赛事已结束，我们在其公开冻结测试集与官方公式上做独立对标，并计划投向下一届。"* 任何材料、视频、答辩里出现"我们参加了 ICME""获得名次"的表述，一票出局。
2. **ICME 数据不外传**。只用于本地训练与评测，不进 Git、不发群、不放公网。对外只报指标，不放原图。
3. **公开数据集按许可用**。MVTec-AD 是 CC BY-NC-SA 4.0（研究用途），VisA / Real-IAD 各自看条款——**写进材料前逐个确认**，别把"能下载"当成"有授权"。
4. **不用真实产线保密图片**。演示只用公开数据或自造样本。
5. **口径三句，全员统一**：
   - 赛场是华为 ICT 大赛赛题二（AgentArts）；
   - 尺子是 ICME 冻结榜；

## 三、质量护栏（数字层面的红线）

1. **QWK 护栏 = 0.89**。任何一次消融让 QWK 跌破 0.89，该改动**回滚**，不许带病前进。
   - 来历：当届冠军 QWK 0.907，第 2–5 名挤在 0.873–0.897，0.89 压在这个簇的上沿——既留向上空间，又不把分级容错压到不可能。
2. **每次消融同时记录三个指标**（mIoU / Macro-F1 / QWK）。攻 mIoU 的改动很容易顺手砸了 QWK，只看一个指标会漏。
3. **未实测一律写「待实测」**。材料里出现一个编的数，整套作废——这是全项目最硬的一条纪律。
4. **复现优先于刷分**。自己的数字必须自己跑出来；对不上论文口径就查口径，**不许悄悄调参凑数**。
5. **不同尺子的数字不进同一张表**（MVTec 与 ICME 分开），引用时注明出处与口径。

## 五、技术禁区（明确不做的，防范围蔓延）

1. **不做**实时产线对接、设备集成——没有真实场景，做了无法验证。
2. **不说**"替代 KLA / AOI 设备"——无独占数据、无装机闭环，纯自杀式表述。
3. **不宣称**首创 / 国内首个 / 填补空白——一查就死，且函评需要的是参照系不是新奇。
4. **不把"多智能体编排"当创新点**——AgentArts 拖拽即有，是平台自带能力，写进材料等于告诉评委我们没搞清平台边界。
5. **不拿本地 127.0.0.1 的服务挂平台**——平台只能走公网，这是官方明文。
6. **不做多模型集成 / 扩散造样本刷分**——消融会说不清，且那是企业队的资源打法。
7. **不在材料里放没出处的数字**——外部数字标来源，不同口径注明（如 KLA 份额 53% 与 32.1% 是两个细分口径，不能混用）。

## 六、单点风险登记（本项目最大结构性弱点）

- **风险**：算法只有 1 人（队员 A）。他卡住，内核全线停。
- **缓解**（唯一有效的一条）：队员 C 紧贴 A——A 跑通 baseline 后，调参、跑评测、跑消融这类重复活交给 C，A 只做攻关。
- **兜底**：第 7 天止损线触发时，内核降级为「预训练 + 后处理」，作品按系统集成型交付，对外不提分数。
