# 开发规范 · 明察 DefectLens

> 来源两块：① 团队既有《开发规范》（语雀导出，云效 CI/CD + Apifox + 阿里巴巴 Java 规范，2026-10-09）；② 本项目特定约定。
> **不适用的条款明确列出**（第七节），别把用不上的规矩当宝贝供着。
> 版本：v1（2026-10-13）。

## 一、仓库与目录规范

```
ICT/
├── README.md                # 仓库门面：一句话 + 目录导航 + 快速开始
├── docs/                    # 全部文档（PRD / 方案存档 / 项目文档 / 起跑清单 / 口径 / 规范）
│   └── competition/         # 比赛官方材料
│       └── private/         # 报名表等私密材料（Git 忽略）
├── prototype/               # 界面原型（HTML）
├── src/                     # 推理服务代码（mock_inference_server.py 在此）
├── agentarts/               # AgentArts 接入说明与接口约定
├── data/
│   ├── raw/                 # 原始数据，只读，不许改
│   └── processed/           # 清洗产物，另存
├── eval/                    # 评测脚本
└── runs/                    # 每次实验的配置与结果 JSON
```

**规则**：
1. 新文件先想清楚放哪一层，**不许在仓库根目录堆散文件**；
2. `data/raw/` **只读**——所有清洗、增强、子集化产物一律写 `data/processed/`；
3. 实验产物（配置、日志、指标）每次运行落一个 JSON 到 `runs/`，字段含：日期、数据集、配置、三个指标；
4. 私密材料（报名表、任何含个人信息的文件）放 `private/` 并确认在 `.gitignore` 里；
5. 模型权重（`.pt/.pth/.ckpt/.onnx/.safetensors`）**不进 Git**。

## 二、命名规范（沿用团队规范）

1. 代码组命名：前端 `xxx_web` / 后端 `xxx_boot`；端口用后**登记到端口表**；
2. 库表名 = `模块前缀简写_功能名`（如 `sys_dict_type`）；基础字段固定 5 个：`id` / `create_id` / `create_time` / `update_id` / `update_time`，**无逻辑删除字段**；
3. 本项目文件命名统一带项目名后缀：`XXX-明察DefectLens.md`，一眼能认出归属。

## 三、Git 规范（沿用团队规范）

1. 走 **SSH**，不用 HTTPS；
2. `master` 主干 + `dev` 开发分支；多人时每人一条 `dev_姓名简称`（如 `dev_lyh`）；
3. 合并前**务必核对冲突**，不许无脑合；
4. 提交信息说清"改了什么、为什么"，禁止 `update` / `fix` 这种空消息；
5. **当前仓库没有远端**——交作品或多人协同前，先建远端并首次推送（待办，见 `任务分工`）。

## 四、接口规范（沿用团队规范）

1. 接口文档用 **Apifox**，环境填 localhost，**必须附成功示例**；
2. 本项目的关键接口只有一个：`POST /v1/inspect`（`src/mock_inference_server.py` 的约定）——它现在是 mock，将来是真模型的**唯一入口**，字段不许随意改；
3. mock 响应必须带 `mode:"mock"` / `demo_only:true` / `image_analyzed:false` 三个标记，**防止假数据混进评测**（现有实现已做到，保持）；
4. 真模型接上时只改这两个标记的值，**接口结构不动**。

## 五、代码规范（沿用团队规范）

1. 过**阿里巴巴 Java 开发规范插件**；
2. 本地数据源各自新建，**不许改别人的账号密码**；
3. Python 侧同样纪律：不硬编码路径（用配置或相对定位）、不提交含密钥的文件。

## 六、部署规范（沿用团队规范）

1. 提交部署前必须把环境切到 **prod**；
2. 云效流水线：Java/Node 构建 → 主机部署（tar 解压）→ `nohup java -jar --spring.profiles.active=prod`；
3. 主机组命名 = **主机 IP**；分支触发须开 Webhook；容器加 `--restart always`；
4. **本项目特需**：任何要挂到 AgentArts 的服务（mock 或真模型）**必须先部署到公网 HTTPS**——平台访问不到本地/内网（官方明文）。公网方案（云服务器 vs 内网穿透）待拍板，见 `任务分工`。

## 七、本项目特定约定

1. **评测口径**：mIoU / Macro-F1 / QWK 三个指标同一次运行里同时算；划分口径不同的数字不进同一张表；脚本由队员 C 维护，算法侧不自己算分；
2. **口径纪律**：对外三句（赛场/尺子/独立对标）不变；未实测一律「待实测」；
3. **文档纪律**：新增文档进 `docs/` 并在 `README.md` 登记；文档里的数字标来源，不同口径注明；
4. **原型纪律**：原型界面上的演示数据必须标注"示意、不代表实测"，开关只触发论文里已有的真实现象。

## 八、不适用的条款（诚实清单）

团队规范里以下内容，**本项目当前用不上**，列出来免得有人瞎折腾：

| 条款 | 为什么不适用 |
|---|---|
| 数据库库表命名、5 个基础字段 | 本项目暂无自建库表需求；若后续建库再启用 |
| 微信 OAuth 登录、模板消息 | 用不到 |
| Docker 装 Node/Vue/Java/Redis/MySQL/Nginx 的部署手册 | 属查阅型；当前部署面很窄（一个推理服务 + 一个静态页面） |
| 云效流水线的 Java/Node 构建段 | 本项目以 Python 推理服务为主，真到部署时按实际技术栈改写，不硬套 |
