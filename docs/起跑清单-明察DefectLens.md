## 一、你（Allen）：半天摸通 AgentArts

**已核到的平台事实（来源：华为云帮助中心 / 官方博客，2026-10-10 抓取）**

- 名称：**智果（AgentArts）**，华为云企业级一站式智能体构建与运营平台。三大板块：**资产广场**（模板 / 模型 / MCP / 插件 / 提示词 / Skill，拿来即用）、**开发中心**（可视化画布拖拽编排）、**运营运维**（全链路 Trace / 评估）。
- **三种开发模式**：单智能体（0 代码点选）、工作流（低代码画布、适合固定流程）、多智能体（配置中控指令，多智能体协同）。
- 能力接入：**MCP**、**自定义插件**（把已有 API 按参数配置接进来）、**RAG 知识库**（Word/PDF/PPT/PNG，关键词+向量混合检索+重排）。
- **公测状态**：产品处于公测，新用户需点"立即申请"→审核开通；**基础版限时免费**（个人体验）、企业版面向团队。**具体权益以平台页面实时信息为准（我未登录核实）。**
- 有 **Python SDK**（面向开发者的工具包），另有开源的 **openJiuwen** 框架（据称与 AgentArts 代码同源 90%+）。

**半天四步（"能用"的标准 = 走完第 4 步）**

1. **开通**：华为云控制台 → 搜 AgentArts → 点申请（若队伍已有账号可跳过）。**若审核慢，今天先做第 2 步以下的准备（写 prompt、画流程、定接口）。**
2. **单智能体最小闭环**：开发中心新建一个单智能体 → 选一个模型 → 写系统提示词（质检员的角色设定）→ 挂一个内置插件（如文件处理/OCR）→ 在调试区跑一次对话，看它能不能调用工具。
3. **接一个自定义插件（关键一步）**：把队友的检测内核包成一个最简 HTTP 接口（**输入图片 URL / 输出 JSON：框 + 类别 + 四档分级**），在平台上配置成自定义插件挂上去。这一步走通 = "外壳能调用我们的真内核"，赛题二的核心合规问题就落地了。
4. **换成多智能体**：按方案里的三角色（**分拣 / 检测 / 仲裁**）配中控指令，让分拣先按置信度分流、检测调插件、仲裁处理 Marginal 边界。**角色必须有各自的输入输出与动作，不是把一次推理拆三个名字。**

**顺手做掉的**：打开「运营运维」看一眼 Trace / 评估长什么样——**答辩时"平台自带观测与效果评估"是要拿来当证据用的**，你得先知道它长什么样。

**半天到什么程度算够**：能对着评委当场说出"这个检测结果是我们的模型、通过自定义插件挂在 AgentArts 上的，这是调用链"。**够了，其余细节边做边学。**

## 二、队友（算法）：内核第一天跑通什么

**目标：今天结束时，屏幕上有一张"分割掩码 + 四档预测"的图，哪怕分数很差。**

1. **环境**：确认卡型（见第四节三问）→ 装 PyTorch + **ultralytics（官方 baseline 用的是 YOLOv8-seg）** 或 detectron2 系（冠军路线 Mask2Former）→ 跑通一个 `import` 级 smoke test。
   - ⚠️ **官方 baseline 仓库里只有代码、没有图片**（2026-10-12 核实）：`github.com/IDAGrandChallenge/idachallenge-baseline`，两个 Track 各一份 markdown 说明 + 代码。**必须自己把数据放进去才能跑。**
2. **数据（不等 ICME）**：拉 **MVTec-AD**（公开可下，15 类工业缺陷，许可证 CC BY-NC-SA 4.0，**仅研究用途**）。
   - ⚠️ MVTec-AD **没有四档严重度标签**，只能先跑"缺陷定位"这一半；严重度头要等 ICME 数据或自造序数标签。**这是 Plan B 的固有缺口，如实说明。**
3. **骨架三件套**（按方案内核分层）：
   - ① 无监督异常筛选（先用简单阈值/现成 anomaly 分数）→ ② 分割骨干出掩码 → ③ 接一个序数头（CORN 或 CORAL，**别用普通 softmax 多分类**，这是论文点名的关键）。
   - ⚠️ **官方 Track 2 baseline 的分级是"手工规则"、不是学出来的**：YOLOv8-seg 出掩码后，取 4 个掩码指标（**缺陷面积、框长宽、平均灰度对比度**）加权打分，再套四档。冠军才换成学习式严重度头。⇒ **"把规则打分换成学习式序数头"就是第一个干净的单变量改进**，而且正好落在 A 的分割本行上。
4. **先算 mIoU**：MVTec 上至少把 S_loc（mIoU）算出来，得到一个真实的数（哪怕 0.3）。**这就是"评测管线通了"的证据。**
5. **产出**：一张图 + 一个数 + 一句 README（怎么跑、跑出什么）。**不写论文式描述，写操作说明。**

**纪律**：在 ICME 数据到手前，**不要**对外报任何"对标 0.811"的说法；MVTec 上的数只能叫"骨架自测"。

## 三、第三队友：数据管线

1. **目录规范**：`data/raw/`（原始不动）、`data/processed/`、`runs/`（每次实验一个子目录）、`eval/`。**原始数据只读，不许原地改。**
2. **评测脚本**：按官方公式先写两个函数——`mIoU`、`Macro-F1`，以及 `QWK`（序数分级）。**先用手造小样例单元测试，保证公式写对**（公式见方案 §3.1）。
3. **消融调度**：写一个能"一次只开一个开关、跑一轮、记录配置+结果到 CSV"的脚本骨架，等模型侧就绪即可开跑。
