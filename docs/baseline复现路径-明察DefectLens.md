## 〇、三个必须先记住的事实（都核自官方论文 arXiv:2607.04675 与 baseline 仓库）

1. **官方 baseline 是 YOLOv8-seg，两个 Track 都是。** 不是 Mask2Former——Mask2Former 是冠军（山东大学 MVP 队）的方案。前面文档混过，以这条为准。
2. **官方 Track 2 的分级是「手工规则」，不是学出来的。** YOLOv8-seg 出掩码后，拿**面积、框长宽、灰度对比度**四个指标加权打分，再套四档。冠军才把它换成学习式序数头。
   ⇒ **「把规则打分换成学习式序数头」就是我们第一个干净的单变量改进**，正中 A 的分割本行。
3. **官方公式：总分 = 0.2 × mIoU + 0.2 × Macro-F1 + 0.6 × QWK。** 冠军 0.811 的构成是 QWK 0.907 / mIoU 0.662 / Macro-F1 0.673——**定位和分类是全场短板，分级已近顶格。我们主攻 mIoU，不碰 QWK 的算法结构。**

**关键仓库**：`github.com/IDAGrandChallenge/idachallenge-baseline`（**只有代码，没有一张图**——数据要走邮件申请，见 `起跑清单 §〇之二`）。

## 一、阶段 0：数据到手之前（今天起 3 天，不依赖 ICME）

**目标**：不等数据，先把环境和管线跑通，报出第一个 mIoU。

**为什么能不等**：MVTec-AD 公开可下（CC BY-NC-SA 4.0，仅研究），15 个类别的异常分割任务齐全。它**没有四档严重度标签**，所以只跑「定位」这一半——mIoU 能算，QWK 算不了。这就够了：阶段 0 要验的不是分数，是**管线通不通**。

**A 的动作（一个人能跑完）**：
1. clone 官方 baseline 仓库，读 README，**把实际依赖和运行命令记下来**（仓库具体要求以现场为准，下面第节有待核项）
2. 装环境，跑通 YOLOv8-seg 在 MVTec-AD 上**一个类别**的推理
3. 跑通训练，报出该类别测试集 mIoU —— **这是全项目第一个实测数字**

**C 的动作（并行）**：
- 写评测脚本骨架：输入「预测掩码 + 真值掩码」→ 输出 mIoU；预留 Macro-F1 与 QWK 的接口（ICME 数据到了再填）
- 脚本输出格式定死：一张表，每次运行落一个 JSON 到 `runs/`，字段含日期、数据集、配置、指标

**验收标准**：
- A 报出一个 mIoU 数字（无论高低，**真数就要**），并说明训练配置
- C 的评测脚本能被 A 直接调用，输出与手工核算一致

**卡点备案**：装不上依赖 → 先记下具体报错，换 ultralytics 官方预训练权重 + 自己的简单训练脚本，**不要耗在环境上超过 1 天**。阶段 0 的目的是验证管线，不是复刻官方配置。

## 二、阶段 1：数据到手（等回信，预计 3–5 天）

**目标**：在 ICME Track 2 上完整复现官方 baseline，拿到三指标的「对标起点」。

**动作**：
1. 数据到了先做三件事，**别急着训**：核对文件结构（Track2 测试集 1156 张图 / 1388 个缺陷实例，论文口径）、确认四档标签字段、确认官方评测脚本的位置和用法
2. 按仓库 README 跑官方 baseline：YOLOv8-seg 出掩码 → 四指标加权规则打分 → 套四档
3. 用 C 的评测脚本算 mIoU / Macro-F1 / QWK，**自己复现出来的数字才是起点**，不直接引用论文里的 0.811

**验收标准**：三指标全部报出，且与论文公布的官方 baseline 数字在同一量级（**对不上就查口径，不许悄悄调参凑数**）。

**数据条款**：一旦拿到 ICME 数据，**不转发、不公开、不进 Git**。对外只报指标，不放原图。

## 三、阶段 2：第一个单变量（复现成功后立刻做）

**目标**：只换一件事——**把四指标加权规则打分，换成学习式严重度头**，其余一律不动。

**动作**：
1. 保持 YOLOv8-seg 的分割输出不变（或沿用冠军的 Mask2Former 骨架，二选一，先记录选型理由）
2. 加序数回归头（**CORN 或 CORAL**，先用一个，不要两个一起上——单变量原则）
3. 端到端训练；冠军的量级参考：2100 次迭代、batch 8、2×A100、约 30 分钟

**为什么先动这个**：它是官方 baseline 与冠军之间**唯一被论文点名的结构性差异**，改完就能回答"我们比官方 baseline 强在哪"。攻 mIoU 的改动（更强骨干、高分辨率、多尺度）全部排在它之后。

**硬护栏（不许破）**：
- **QWK 任何一次消融低于 0.89，该改动回滚**，不许带病前进（0.89 的来历：冠军 0.907，第 2–5 名挤在 0.873–0.897，0.89 压在这个簇的上沿）
- 每次消融**同时记录三个指标**——攻 mIoU 的改动很可能顺手砸了 QWK，只看一个指标会漏

## 四、评测口径（C 全权负责，A 不自己算分）

| 规矩 | 原因 |
|---|---|
| 三指标同一次运行里同时算 | 防止挑指标说话 |
| 每次运行落 JSON 到 `runs/`，字段含日期/数据集/配置/指标 | 消融要可回溯 |
| 划分口径不同（MVTec vs ICME）的数字**不许放进同一张表** | 两个尺子不能混 |
| 未实测一律写「待实测」 | 这是全项目最硬的一条纪律 |
