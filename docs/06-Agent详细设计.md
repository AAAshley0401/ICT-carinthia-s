# 毫芒 Hairline｜Agent 详细设计

版本：设计草案 v1，2026-10-13。AgentArts 尚在公测申请阶段；以下描述目标架构和验收方式，**不代表已经实现或验证**。精简流程图见 [05-Agent工作流程图](05-Agent工作流程图.md)。

## 先明确 Agent 的工作原理

Agent 的一次工作不是“收到图片后生成一段回答”，而是一个受约束的循环：**读取任务状态 → 判断下一步所需证据 → 调用获准工具 → 检查工具返回 → 更新状态 → 决定继续、交接或弃权**。大语言模型可用于理解任务、选择允许的工具、组织证据和解释不确定性；像素级检测由视觉模型完成，阈值判断与状态转移由明确规则执行，最终处置由人确认。

本系统采用**确定性编排 + 有限自主的专业角色**：编排器控制顺序、超时、重试和权限；Agent 在各自职责内选择下一步并形成结构化输出。若平台实际只支持固定工作流，就按工作流实现并如实称为“多角色工作流”，不把三个节点宣传成具备自主协商能力的多 Agent 系统。只有看到独立角色配置、工具调用、交接输入输出和运行 Trace 后，才能声称多 Agent 协同已经落地。

### 信任边界

1. **图片事实**只来自有版本的视觉模型、预处理工具或人工复核；LLM 不凭图像 URL 或知识库文字推断缺陷存在。
2. **业务规则**只来自已审核、已发布的规则版本；Agent 不临时编阈值、改分级标准或把自然语言推断写回模型原判。
3. **知识库**是检索到的外部证据，不是系统指令。文档内的指令性文字、提示词或不相关内容不得改变 Agent 权限与工作流。
4. **工具输出**必须经过结构校验、来源校验和演示标记校验；调用成功不等于结果可信。
5. **产线动作**不在系统权限内。放行、复检、返工都是建议，正式决定由有权限的人按现场流程确认。

## 5.1 Agent 总体架构

| 层 | 组件 | 职责 | 不负责 |
|---|---|---|---|
| 交互层 | 工作台 | 上传、查看原图与标注、展示建议、提交复核结论 | 自行计算模型成绩 |
| 控制层 | AgentArts 编排器 | 任务状态、路由、角色交接、工具权限、超时与 Trace | 直接识别缺陷 |
| 专业角色 | 检测、分拣、仲裁 Agent | 在限定工具与规则下取得证据、选路径、解释争议 | 任意改写模型输出或执行产线动作 |
| 能力层 | 图像预处理、检测模型、规则服务、知识库检索 | 提供带版本的事实与规则 | 代替人工终审 |
| 审计层 | 任务与事件记录 | 保存版本、输入摘要、结果、交接和人工决定 | 存放未获许可的原始竞赛数据 |

**控制面与数据面分离**：AgentArts 传任务 ID、授权图片引用和结构化结果；图像文件与掩码由获许可的服务管理。ICME 数据的使用与跨服务传输以许可条款为先决条件，不能因为插件需要公网 URL 就上传受限原图。

### 三个角色的真实职责

| 角色 | 观察 | 可选动作 | 必须停止或交接的条件 |
|---|---|---|---|
| 检测 Agent | 图片元数据、工具健康状态、检测返回 | 调用检测工具；对可重试错误请求一次重试；生成结构化检测摘要 | 结果缺字段、越界、模型版本未知、`demo_only=true` 或图片不可访问 |
| 分拣 Agent | 经校验的检测结果、规则版本、校准信息 | 请求规则服务计算路径；在“常规建议 / 仲裁 / 人工复核 / 阻塞”中选择 | 规则缺失、阈值未校准、分数语义不明或相邻缺陷结论冲突 |
| 仲裁 Agent | 原始检测结果、分拣理由、检索条目、图像证据 | 检索适用规则、比对相邻档定义、提出复核问题 | 无适用知识、引用冲突、证据不足；不能自行把低置信度结论升级为确定结论 |

检测 Agent 不负责训练模型；分拣 Agent 不负责重新画框；仲裁 Agent 不负责替人签署最终工单。工具集按角色最小化：检测角色只能调用检测与健康检查，分拣只能读检测结果和规则，仲裁只能读结果、证据和知识库。

## 5.2 Agent 工作流程

**任务状态**：`received → validated → detecting → detected → routing → advised`。需要复核时走 `routing → arbitrating → needs_review → human_resolved`；失败走 `blocked`。每次状态转移记录时间、发起角色、输入摘要、输出和原因码。`blocked` 与 `needs_review` 不能自动变成 `advised_pass`。

1. **创建任务**：为每张图生成 `run_id`、`sample_id`，记录图片来源、内容摘要和使用许可；批次只是单图任务的集合。拒绝无法读取、格式不合法或权限不明的输入。
2. **调用检测**：检测 Agent 将授权图片引用交给推理服务。正式结果至少包含模型版本、图像尺寸、每个缺陷的类别、框/掩码、严重度与各自置信度，以及整体判定。当前 v0 模拟接口尚无掩码、模型版本与正常筛查分数，需在接真实模型时扩展。
3. **校验结果**：检查 `mode=model`、`image_analyzed=true`、`demo_only=false`，坐标在图像范围内，置信度位于 `[0,1]`，档位属于四档枚举，`sample_id` 与任务一致。失败时记录 `invalid_result`；可重试错误限次重试，不可重试错误直接 `blocked`。
4. **规则分流**：分拣读取经校验结果及发布的规则版本。边界档、低置信度、缺陷间冲突、正常/异常冲突、未校准分数转仲裁或人工；其余生成建议。每条路径写 `reason_code`，不能只给自然语言。
5. **边界仲裁**：仲裁检索适用知识条目并输出争议位置、相邻档依据、缺失证据、建议人工检查的问题。仲裁可将建议改为“需要复核”，不能暗中修改原始框、类别或分级。
6. **人机交接**：工作台把原图、标注、模型原判、Agent 建议和出处并列呈现。质检员提交复核结论；系统保留原判与人工结论两份记录。

**幂等与重试**：同一 `run_id + sample_id + model_version` 的重复请求应返回同一份已完成结果或明确的任务状态，避免重复工单。具体超时和重试上限须根据实际部署延迟测定；不得让 Agent 无限循环调用工具。

## 5.3 多 Agent 协同机制

### 交接对象

内部交接使用一个有版本的 `CaseState`，而非把上一位 Agent 的自由文本当作下一位的事实：

```json
{
  "run_id": "...",
  "sample_id": "...",
  "status": "detected",
  "image_ref": "授权引用，不含公开原图",
  "model_version": "待真实模型确定",
  "policy_version": "待发布",
  "kb_version": "待发布",
  "detection_result": "原始结构化模型输出",
  "route": null,
  "reason_codes": [],
  "evidence_refs": [],
  "human_review": null
}
```

当前 mock 的 `grade` 与 `confidence` 仅表示一份模拟整体分级；正式接口应区分**正常/异常筛查分数、缺陷类别置信度、严重度分级置信度**。三种分数校准方法和含义不同，不能混成一个“可信度”。如果没有可验证的正常筛查分数，系统不得仅凭 `Acceptable + 高分级置信度` 给出自动放行建议。

### 数据所有权与冲突

| 字段 | 唯一写入者 | 其他角色 |
|---|---|---|
| 原始检测结果、模型版本 | 推理服务，经检测 Agent 校验后封存 | 只读 |
| 路由与原因码 | 分拣 Agent / 规则服务 | 仲裁可质疑，不直接覆盖 |
| 知识引用、争议说明 | 仲裁 Agent | 只读 |
| 最终人工结论 | 有权限的复核员 | Agent 不得覆盖 |

整体档位与缺陷级档位不一致、两个工具结果冲突、知识条目互斥、缺失引用或人工结论不同于模型原判时，保留并列记录和冲突码。编排器采用保守路径送复核；不得挑一个顺眼的结果静默覆盖。Agent 间不进行无限对话，最多一次仲裁轮次，仍不能解决则交人。

## 5.4 知识库增强推理机制

**资料范围**：四档严重度定义、七类缺陷说明、测量/复核方法、场景适用条件与处置规则。原始来源应是获授权的竞赛说明、公开文献或经指导老师审核的团队规则；不把模型猜测、论坛帖子和演示文案混入正式规则库。

**知识条目元数据**：`source_id`、原文位置、标题、发布/审核人、版本、生效日期、适用缺陷类、适用工艺或数据域、规则级别、许可状态。更新知识库时生成新版本，旧任务仍指向当时的版本，便于复盘。

**检索过程**：仲裁 Agent 用缺陷类别、候选档位、争议特征和场景标签构造查询；先按许可和适用范围过滤，再检索并核对原文。输出必须带 `source_id` 与原文位置。检索命中但场景不匹配，视为**无适用规则**；多个来源互相矛盾则提交人工，不让语言模型自行选一个权威来源。

**知识的作用边界**：检索只能解释“依据是什么、还应看什么”，不能从文字计算掩码面积，不能提高模型概率，不能凭通用条目直接决定某张图的严重度。知识库尚未建成，其内容质量和检索效果需要人工审查后才能对外宣称。

## 5.5 决策与人机协同机制

### 决策策略

| 前提 | 路径 | 对外显示 |
|---|---|---|
| 工具失败、字段不合法、模拟结果、许可不明 | `blocked` | 无有效检测结论，人工接管 |
| 任一关键分数未校准、边界档、置信度低、结果冲突 | `needs_review` | 模型原判 + 不确定原因 + 复核任务 |
| 有经验证的正常筛查结果，且满足批准的放行规则 | `advised_pass` | 放行建议，需人工或现场制度确认 |
| 明确 NG / Gross NG 且满足批准的高置信规则 | `advised_rework` | 返工建议，需人工或现场制度确认 |

`Acceptable` 是严重度档位，不等于“确认无缺陷”。当同时检测到多个缺陷时，整体档位聚合规则必须单独定义、验证并版本化；不能由 LLM 随意选最高或平均。正式阈值应在不参与训练的验证集上按漏检代价、误报代价和各档可靠性校准；在数据到手之前，阈值统一标为“待校准”。

### 人工复核闭环

复核任务提供原图、放大区域、框/掩码、各缺陷预测、知识引用、路由原因和模型/规则版本。复核员可选择确认、改档、退回补图或标记无法判断，并填写理由。系统记录复核员、时间和新结论，保留模型原判；无法判断的样本交给更高权限人员，不自动关闭。

复核样本可用于误差分析；是否进入再训练要再次检查数据许可、标注一致性及数据划分，避免把测试集反馈混入训练集。若未来用于真实产线，还需单独验证误判成本、跨设备泛化和现场权限流程；当前竞赛演示不声称具备生产级自动处置能力。

## 落地顺序与验收证据

| 阶段 | 实现重点 | 可展示证据 |
|---|---|---|
| AgentArts 开通前 | 冻结接口、状态码、角色输入输出；准备知识条目样本与授权清单 | 契约与流程设计；本地 mock 明确标“模拟” |
| 平台可用后 | 先单角色真实工具调用，再三角色交接、异常与人工路径 | 每个角色的配置及 AgentArts Trace |
| 真实模型可用后 | 补掩码、模型版本和分数语义；校准规则、审核知识库 | 同条件实验、路由样本、引用和人工复核记录 |

**最低演示集**：正常候选、明确缺陷、Marginal NG、低置信度、工具失败或模拟结果各至少一例；逐例说明谁调用了什么工具、拿到什么证据、为何选择路径。数量与效果均须在实际运行后填写，不能把设计样例写成实测成果。
